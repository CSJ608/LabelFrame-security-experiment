# Skill: comment-check——注释卫生与文档同步核查

## 背景（判据出处）

- **决策 #187**：源码注释禁过程标记（迭代号 / 决策号 / Issue 引用含裸 #N / 方案轮次 / PR 引用 / AC 编号 / 返修轮次 / salvage / 评审拍板决议）。
- **决策 #189**：注释极简化——保留一句话「对象用途与功能」summary＋白名单四类（不变量 / 平台坑 / 兼容义务 / 防回归警示，判据＝去掉会重踩踩过的坑）；机制 / 契约 / 取舍叙述由 docs/design/ 承载。
- **决策 #189 ④**：迭代涉及模块结构 / 接口契约 / 关键机制实质变化时，AC 须含「docs/design/ 对应篇同步」条目。
- 字符串域（测试夹具 / 断言消息 / describe / it 标题 / CLI Usage 文本）按既定口径**不动**。

## 核查流程

1. **确定基线**：用户指定 base（ref / 提交号）优先；未指定时用最近 `v*` tag；再无则问用户或取可视范围内合理基线并说明。
2. **机器扫描**：
   - `python scripts/check-comment-hygiene.py <base>`（A：过程标记，确定级）
   - `python scripts/check-comment-hygiene.py <base> --full`（B：结构变化-文档同步启发式，提示级）
3. **语义抽查（#189 尺度，机器测不了的部分）**：对 diff 新增注释抽样通读——机制长叙述堆在代码里（应进文档）、文档中行数 / 文件清单断言 grep 实测是否过时、白名单保留是否到位。
4. **输出分级报告**：
   - **确定违规**（A 命中）：逐条列 文件:行 + 违规类型 + 建议改写（删标记留约束）；
   - **尺度存疑**（语义抽查发现）：列出处与倾向；
   - **文档过时**：docs/design/ 哪篇哪节与代码不符；
   - 提示级（B 命中）：哪些提交可能触发 #189 ④。
5. **只报告不动手**——用户明确说"修"才进入修复模式。

## 修复模式（用户明示后）

1. python 批量替换：每条 assert 命中且唯一；**脚本中途失败重跑须幂等**（old 不在则验证 new 已在）；
2. 剥离原则（136 判例）：删过程标记前缀，**约束 / 回退语义 / 兼容义务文本完整保留**；「见 #N 范围外」类改写为无引用句式；多行块注释只删标记文本不动结构；
3. BOM：二进制读判 BOM，utf-8-sig 处理后按原样写回；
4. 复扫：`check-comment-hygiene.py <base>` 零命中；
5. 零逻辑自证：全文归一化对比（剥注释后代码行逐行一致；git show 与工作区都用 utf-8-sig 解码防 BOM 假差异）；
6. 文档同步：过时断言逐条回读代码更新；
7. `dotnet build/test`（排除 Perf/Soak）＋涉 web 改动加 `pnpm lint / test / build`；
8. 短分支＋PR＋squash，Conventional Commits 中文；修复清单与验证证据回 Issue。

## 已知坑（修复时必读）

- python 多行字符串匹配撞 CRLF——拆单行替换；
- 批量脚本挂掉后部分文件已写盘——重跑幂等；
- `nul` 等 Windows 保留名残留文件删除须 python `\\?\` 前缀路径（bash 内联转义会坏，写临时脚本执行）；
- 字符串域违规（describe 标题含决策号等）**不在修复范围**，报告里注明即可。
