# Windows 客户端自动升级设计

任务：[#452](https://github.com/marci-labs/LabelFrame/issues/452)，承接安全重启 [#451](https://github.com/marci-labs/LabelFrame/issues/451)。基线 `7405cfb`。

## 使用策略

普通办公电脑默认「自动下载，确认安装」；专用常驻打印终端可以显式选择「维护时间自动安装」，默认本地 02:00–04:00，允许跨午夜窗口；另有「仅提醒」。窗口相同起止时间视为无效，不解释为全天。系统休眠/离线错过窗口则等下次窗口，不补做白天静默安装。后台检查与错峰下载由宿主负责，关闭设置页仍执行；连接旧服务端时明确显示不支持，现有手工下载继续可用。

静默安装同时要求：维护时间内、界面隐藏、最近 10 分钟没有界面交互、无未保存/在途界面操作、整批作业完成或取消、无挂起作业、无路由领取和待确认结果。后台不在批次间隙插入升级，不中断打印，不重启操作系统。手动「安装并重启」可以在显示界面时执行，仍须通过全部业务和编辑保护。

## 发布与信任

1. 既有 `/api/client-packages` 上传仍是手工分发草稿，不触发执行。新更新发布端点先复制独立快照，再验证真实 MSI；旧目录上传覆盖、删除均不能改写已发布快照。
2. 校验固定产品名/制造者、Client UpgradeCode、ProductCode、真实三段版本、x64 架构、大小、SHA256、签名发布者；文件名版本必须与真实版本一致。新包还须提供已签名的服务端版本范围和 .NET 运行时主版本元数据。拒绝错误产品、架构、损坏/未签名/发布者不符、同版覆盖及不兼容包。
3. 发布内容与设备范围一经发布不可改；可暂停/恢复。全量或指定设备 ID 分批推广由管理员明确选择，重新安装前再次确认仍发布且仍适用，不凭文件名最高版本执行。
4. 发布/暂停/校验端点使用独立高熵管理口令，并限制为 TLS 或回环请求、核对 Origin；未配置则拒绝管理，不退回无鉴权。口令通过服务端配置部署，界面仅在内存使用，不存 localStorage，不写日志。此权限仅覆盖升级发布，不声称已为既有打印 API 建立完整账户体系。
5. 固定发布者公钥来自当前可信 Release 的自签证书，作为公开 `.cer` 随 Server 与 Client 发布；首次管理员手工安装建立应用信任。Windows 直接验证 CMS 签名、固定证书 SHA256、有效期/代码签名用途，再调用 MSI SIP 验证包的 Authenticode 内容摘要；Linux 使用 `osslsigncode` 与 `msiinfo`，指定应用私有可信证书并核对叶证书指纹。两端均不导入操作系统根证书，不用「忽略签名错误」代替校验。私钥只留原发布 Secrets，仓库仅存公钥。
6. 证书轮转须由当前可信发布者签名的客户端/服务端升级或管理员再次部署完成；移除旧信任后旧发布者不能自动安装。证书过期时停止自动执行，不静默放宽验证。

## 受限安装执行

Client MSI 安装 `LabelFrameClientUpdater` Windows 服务，入口只运行更新通道，不加载打印/界面。普通客户端保持原用户身份。服务不提供任意 URL、路径、命令、参数或远程 HTTP 执行接口；仅接收本机命名管道传入的有界 MSI 字节和摘要标识，独立复制到受保护缓存后重新完整验证，并与本机已安装 Client 真实版本比较，拒绝同版重放与降级。

命名管道拒绝网络/匿名身份，识别真实客户端进程，检查其可执行文件位置；安装目录、执行器和缓存必须受管理员/SYSTEM 保护，发现用户可写路径或重解析点则拒绝。缓存/日志只使用服务产生的 GUID，不采信请求路径。首次管理员安装完成此通道；旧版客户端需人工升级一次。

维护准备复用安全重启门闩。服务先验证并启动独立、固定内容的安装监督进程，普通用户同时启动独立重新拉起进程；两者均确认就绪后旧客户端才退出。监督进程等待准确旧 PID/启动时间退出，不强杀；通过固定 `msiexec /i ... /qn /norestart REBOOT=ReallySuppress /L*v ...` 执行。监督进程不加载正在更新的宿主程序集，避免 MSI 停服务时丢失安装结果或锁文件。普通用户重新拉起进程读取受保护结果，以原身份/配置启动客户端；SYSTEM 不启动交互窗口。

管道实际采用两阶段提交：服务完成包验证后返回事务标识，客户端先原子保存恢复记录并确认原用户等待器就绪，再发送同一管道的提交帧。服务此时才创建安装监督进程，收到就绪标记后原子写入受保护的安装提交文件；无提交文件的监督进程 15 秒内取消，不执行 MSI。提交后的确认丢失不能解除业务冻结，客户端交由已就绪的原用户等待器恢复。服务管道 PID 还必须等于 SCM 中正在运行的更新服务 PID，防止其他用户抢占同名管道冒充更新器。

每台机器同一时间只允许一个安装事务。安装失败不反复自动重试；超时/失败/3010 均留痕并给出恢复方式，不强制操作系统重启。Windows Installer 自有失败回滚可保留旧版，但现有 MajorUpgrade 禁降级，不能把「自动降级回滚」当作已实现能力。

每个安装请求最长 3 分钟准备，包最大 64 MiB；监督进程首次冷启动最多等待 60 秒取得真实就绪文件，提前退出或到期未就绪均失败，不以进程创建成功代替就绪。未保留的失败上传立即删除，完成事务保留最近四个，加上当前事务最多五组包和日志。安装结果原子落盘，原用户等待器最长等待 20 分钟，超时显示错误并留文件，不强杀仍在运行的 Windows Installer。安装失败版本标识持久化，重启后仍需人工明确重试。

原用户等待器取得就绪文件后仍须存活，最多等待旧父进程 3 分钟，覆盖冷启动与提交准备耗时；旧客户端没有退出则等待器自行结束，不强制退出客户端。

## 恢复与真实健康

安装前保存版本、连接方式、已加载插件及服务端的健康快照。重启后先保持业务门闩，再验证实际宿主版本、本地 API、插件 loaded/loadError、原连接未变成 Log、路由重新注册；通过后解除维护并回报成功。检测到旧版完整恢复时报告安装失败并恢复原业务；版本/插件/连接异常则保持业务保护并显示需管理员修复，不能以模拟打印作为更新成功。

恢复检查正在执行时拒绝另一次维护。失败进入需修复状态后，管理员可修复原安装并使用常规设置或托盘的一键重启重新检查；此路径保留已经冻结的队列，等待器失败时也不能解除打印保护。

可信 MSI 附带的官方插件在启动扫描前比较真实版本、更新已激活/已安装官方插件；第三方目录和手动 DLL 不覆盖。单个插件失败需显示，不能清除异常冒充成功。数据、模板、配置和请求幂等键保留。

MSI 的运行中升级预检先读取 `Win32_Service` 中 `LabelFrameClientUpdater` 的进程 ID，并从候选宿主中排除，再按命令行排除 `--update-service` 与 `--restart-wait`。普通权限启动安装时可能读不到 LocalSystem 进程命令行，不能仅依赖命令行识别服务；服务由 Windows Installer 的 ServiceControl 停止。未知角色但非服务的进程不因命令行缺失被跳过，仍执行原有 API 安全退出预检。服务查询失败阻断安装，不降级到不安全的仅进程名选择。

安装预检由 WiX Util 的 x64 `WixQuietExec` DLL 同步运行，命令通过前置属性动作设置，仍位于 CostFinalize 后、InstallValidate 前。QuietExec 从创建进程时隐藏控制台并将输出写入 MSI 日志，非零退出码继续阻断安装；固定使用 System64Folder 下 Windows PowerShell，避免 PATH 解析。安装向导与正常 UAC 保持可见，不能用异步启动或忽略返回码达到隐藏效果。依据：[WiX Quiet execution 官方文档](https://docs.firegiant.com/wix/tools/wixext/quietexec/)。

## 状态与契约

更新状态采用独立数据面，记录客户端版本、候选版本、阶段、延期/失败原因、检查时间、安装事务 ID；服务端按设备显示最近状态及上报时间，超时状态不当作实时事实。下载中断删除临时文件，退避且带错峰；缓存只复用完整摘要匹配的包，执行前重新校验。暂停发布或设备移出范围会取消安装资格。

发布存储不可写或失败包清理异常时，仍释放发布互斥锁；管理员修复存储后可重新发布，无需重启服务。

### 端点

| 端点 | 权限与用途 |
|---|---|
| `GET /api/client-updates` | 管理口令；已发布版本及范围 |
| `POST /api/client-updates/publish` | 管理口令；`fileName` 草稿快照校验后发布，`devices=[]` 为全量 |
| `PUT /api/client-updates/{id}/pause` | 管理口令；只改 `paused` |
| `GET /api/client-updates/candidate?deviceId=&currentVersion=` | 设备可读；按真实版本、范围、暂停和当前 Server 兼容范围选择最高候选 |
| `GET /api/client-updates/{id}/package?deviceId=&currentVersion=` | 设备可读；下载前重新检查候选资格 |
| `POST /api/client-updates/status` | 有界客户端自报状态；不作为设备身份认证或实时健康证明 |
| `GET /api/client-updates/status` | 管理口令；含接收时间的设备自报状态，最多 1000 台，服务重启后重新汇集 |
| `GET /api/host/update` | 本机同源；有效设置和后台状态 |
| `PUT /api/host/update/settings` | 本机同源；保存 `mode/windowStart/windowEnd` |
| `POST /api/host/update/check` | 本机同源；立即检查与按策略下载 |
| `POST /api/host/update/install` | 本机同源；明确安装并安全重启，仍检查业务门闩 |

首次检查错峰 5–60 秒，正常检查间隔 10 分钟加随机延迟，后台每 20 秒检查维护条件并上报状态；网络失败指数退避，最长约 30 分钟。关闭设置页不会停止代理。前端全局更新提示只读状态，表单未保存更改进入已有界面活动保护；安装请求本身不登记为阻塞自己的界面写操作。

客户端更新端点只允许本机同源管理；服务端保留原下载 API，新更新端点是加法，不修改模板包、打印 API、作业模型。PDA/Linux 自动升级、Server 自更新、差分更新、购买证书、CI/流程治理和发版 tag 均不在本轮。

## 平台依据与验证

- [Microsoft：CryptSIPGetSignedDataMsg](https://learn.microsoft.com/en-us/windows/win32/api/mssip/nf-mssip-cryptsipgetsigneddatamsg)、[CryptSIPVerifyIndirectData](https://learn.microsoft.com/en-us/windows/win32/api/mssip/nf-mssip-cryptsipverifyindirectdata)：取签名与验证包摘要分开执行。
- [osslsigncode 官方源码](https://github.com/mtrojnar/osslsigncode)、[msiinfo 手册](https://manpages.debian.org/testing/msitools/msiinfo.1.en.html)：Linux MSI 验签与元数据读取，不依赖文件名。
- 测试覆盖发布权限/暂停范围/不可覆盖、损坏和重放、策略窗口/忙态延期、保护目录/协议边界、安装结果与健康失败；真实浏览器取证。完整标准用户静默 MSI 与真实插件恢复在隔离 Windows 验收，权限不足时明确欠账，不在现有工作客户端试装。
- 真实 MSI/监督子进程回归在测试程序集中串行运行，避免原生冷启动与打印时序用例争抢调度；仍执行真实签名、父进程退出和用户身份断言。
