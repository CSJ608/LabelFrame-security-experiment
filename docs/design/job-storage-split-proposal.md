- `jobs` 保持；`job_items` 保留 id、job_id、item_index、status、error_code、error_message、updated_at；载荷表以 item id 为唯一关联保存原文本和可空二进制。

## 正向迁移方案

空间预检不能使用 `Path.GetPathRoot`：Unix 的 `/data`、容器卷或绑定挂载可能与 `/` 不同。按实际库路径及同目录备份目录分别查询；Unix .NET DriveInfo 按传入路径执行 statfs/statvfs，Windows 使用接受目录路径的 GetDiskFreeSpaceExW（DriveInfo 在 Windows 会归一到卷根）。文件链接指向其他目录时检查最终目标父目录及原备份父目录，目录链接由操作系统解析。两处都要求原保守余量，查询异常/不足均在创建备份前失败，不回退到根分区、不吞异常。配额、并发占用和挂载变化仍由现有 SQLite 原子事务兜底，不承诺容量预留。

依据：[.NET Unix 空间实现](https://github.com/dotnet/runtime/blob/v10.0.13/src/native/libs/System.Native/pal_mount.c)、[Windows 路径空间 API](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw)。

1. 宿主停止消费/提交后、Worker 启动前独占维护；同库多实例必须有可靠互斥，不能仅依赖某个对象的内存锁。
2. 识别明确 schema 版本，未知未来版本拒绝打开；兼容有/无 command_bytes 的旧库。不能沿用吞掉迁移异常后继续启动的方式。
3. 创建一致性备份并做空间预检，禁止生拷正在写入的 db 而遗漏 WAL。备份是迁移失败兜底，不是带新作业运行后的降级方案。
4. 单事务复制载荷、重建状态表、恢复原约束与索引，核对双向一一对应及全部字段，最后更新版本标识并提交。失败或取消回滚，原库可用；不在事务外先清空旧载荷。
5. 提交后做完整性验证再开放 Worker；重启可识别已完成迁移，不能重复复制或重置任何状态。

当前实现覆盖混合字段往返、已知旧 schema、取消、真实 SQLITE_FULL、跨进程锁争用及强制结束后的恢复；真实断电、大历史库磁盘峰值仍待覆盖，具体证据以本地工作记录为准。

## 产品实现验收清单（逐项验证中）

### 独占锁竞争与重试边界

多个旧库初始化者会从无池识别进入各自的维护连接。WAL 连接在获取独占锁时可能持有阻止其他申请者升级的底层锁，单条命令在同一连接等待不能解除循环竞争；原1秒等待耗尽可导致四个初始化者全部失败。识别事务与连接原有释放路径保留，不归因于图片生成，也不通过放宽至少一个成功的断言解决。

仅维护连接打开、设置独占模式及首个锁事务属于可重试阶段：SQLITE_BUSY 最多尝试三次，每次失败先 Dispose 整条无池连接，释放该次 SQLite 锁，再随机退避50～150ms；取消在每次尝试和可取消退避处检查。每次原生命令超时仍为1秒，不承诺严格墙钟时限或即时取消。最后一次 busy 原样抛出，不吞掉或解释为初始化成功；持续旧宿主/读者/空闲运行池占用仍失败。跨进程依赖 SQLite 锁，不增加进程内路径锁或新公共契约。

取得独占锁后，版本/schema/空间检查、备份及转换均在该连接上完成，不进入重试环；因此不会因备份后失败而重复创建备份或在线重做迁移。竞争获胜者原子完成后，后来的维护连接重新识别目标版本并返回无变更；正常并发仅有一份备份。既有回滚、未知结构拒绝、备份完整性与逐张持久性保持。

### 实施细化：迁移内核先行

先实现内部迁移器并在独立临时库验证，再接入存储初始化与维护入口。使用 `PRAGMA user_version` 标识旧格式 0 / 分表格式 1；未知版本或不匹配的表结构拒绝迁移。迁移连接不使用连接池，设置 SQLite `locking_mode=EXCLUSIVE` 后获取并提交独占事务，连接持续持有数据库锁；备份和随后转换期间不释放连接。无法获得锁时失败，要求关闭全部使用该库的进程后重试，不终止其他进程。此锁由 SQLite 跨进程协调，不靠路径命名的内存锁，也不提供在线降级。

使用 SQLite 备份 API 生成同目录、唯一命名且不覆盖的完整备份（包含 WAL 中已提交内容），检查备份完整性后才开始转换。磁盘预检按当前逻辑页大小的四倍加 64 MiB 余量保守估算；这是拒绝明显不足的预检而非容量保证，配额/并发占用/实际文件系统故障仍由事务回滚保护。备份不自动删除，失败保留诊断路径；不自动恢复陈旧备份。转换使用临时表、双向 EXCEPT 字段核对和一一对应检查，最后原子交换并写版本；不执行 VACUUM、不改变 synchronous。额外自定义触发器、视图或索引须显式拒绝，避免重建悄悄丢失未识别结构。

产品初始化与读写现已使用分表，维护工具使用内部友元程序集，不增加公共作业 API。README/DEPLOY/CHANGELOG 已同步数据降级约束；工具尚未进入安装包或 Android APK，实际平台可达性见部署指南。

内核对已知 CREATE TABLE / INDEX 定义实施白名单：保留旧文本库、二进制列原位创建及末尾 ADD COLUMN 三种历史形态，以及内部正反向重建形态；仅归一空白、大小写及 SQLite 重命名生成的 job_items 表名引号。不接受任意“语义近似”手工 schema，额外 CHECK / DEFAULT / COLLATE / 外键级联、同名异构索引和必需索引缺失均在备份前拒绝。sqlite_ 系统对象前缀按字面匹配，不能用 LIKE 的下划线通配符漏掉未知对象。

备份路径分配后的故障保持原异常类型，并在 Exception.Data 附带 JobStorageBackupPath / JobStorageBackupVerified；后者仅在备份完整性检查通过后为 true。空文件或未校验备份仍保留但不能视为恢复依据，维护 CLI 已输出这些诊断字段。取消在锁后、备份前后、复制后和提交前边界检查；Microsoft.Data.Sqlite 同步备份及单条原生 SQL 的执行期间不承诺立即中断，取消在下一可检查边界生效，不能据此宣称毫秒级取消响应或断电安全实证。

- 新库、旧文本库、混合载荷库迁移；重复初始化；迁移中异常/取消/磁盘不足恢复；并发实例互斥。
- 同事务写入、重复 requestId、重复 item id、空作业、缺失/孤立载荷拒绝；所有公开完整查询字段及错误契约不变。

- 新格式运行后反向迁移，旧存储代码读取与继续作业；升级/降级往返不得丢失新作业或重放已完成项。
