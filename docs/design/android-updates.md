# Android 受控 APK 升级设计

任务：[#474](https://github.com/marci-labs/LabelFrame/issues/474)，预研 [#473](https://github.com/marci-labs/LabelFrame/issues/473)。本文描述当前实现与平台边界。沿用 [Windows 更新](client-updates.md) 的受控策略，不复用 MSI 执行器。逐项验收状态以 Issue 和证据为准。

## 当前交付范围（用户批准修订）

后续用户进一步收简：移除独立更新菜单，版本状态与唯一更新按钮嵌入「本机信息」；不提供管理员故障处理入口。后端审计/恢复能力保留但无普通界面入口，异常提示联系管理员，用户接受必要时人工卸载重装会丢失本机数据；产品不自动卸载、清数据或解除未知。设备名未保存时阻止更新；开始更新时仅在确认名称未改后释放本页编辑 lease，并暂时禁用名称编辑/保存，防止本机信息页自身阻断安装或出现检查后编辑竞态。其他配置页保护不变。此段替代下方早期独立页与管理员入口描述。

前一轮独立页收简规则（入口已由上段最新修订替代）：无候选且检查成功显示「已是最新版本」，有候选显示「发现新版本」与唯一「更新」按钮。检查失败不能冒充已是最新。点击更新保留一次三秒防误触确认，随后按需引导安装许可，回到前台后继续准备并自动打开系统确认；不要求用户操作三个技术步骤。只有本次用户发起且页面仍在前台才自动衔接，离页或进程重建不自动弹窗。已有待确认会话仍通过同一个更新按钮继续，不重复创建会话。业务阻挡展示简明行动提示。诊断、健康重试和人工恢复收纳在管理员故障处理入口，不常驻普通主界面；后台验签、业务门闩和新进程健康核验不变。

真机验证补充：无候选时清理缓存允许父目录尚未创建或已被系统回收，只忽略目录不存在，其他 IO 异常仍上报。原生准备安装失败的诊断在更新页保留至下一次尝试，不能只显示通用短暂 Toast。实际设备证据与尚欠验收见 [基线与真机记录](../evidence/172/device-baseline.md)。

2026-10-27 安全交接实测后，用户批准先交付「后台下载＋系统确认安装」。当前服务端只接受确认安装策略，客户端不调用厂商安装接口、不提供静默开关或维护窗口；私有缓存写入系统 PackageInstaller Session 后 fsync，系统负责安全安装交接。未知来源安装权限须用户显式授予；后台不弹安装界面。取消、权限未授予、提交结果不明和恢复失败均需明确展示，不当成功。

静默安装恢复条件为厂商提供可验证安全接口/固件并重新获得用户批准。签名、版本、设备范围/暂停、整批作业/路由/编辑保护与事务健康要求不因范围裁剪而减少。AC-05/07/09/10 修订见 Issue 正文。

## 边界与入口

### 简化维护（用户批准，2026-10-27）

部署目标是可信局域网下沿用现有 Docker 镜像与资源包升级流程，不新增独立服务、设备认证系统、领取围栏或现场 Android SDK 配置。容器内校验工具应由产品镜像携带；自定义签名仍允许覆盖可信指纹，不从上传包自动建立信任。

正常升级保留同签名、完整性、禁止降级、整批/挂起/编辑保护和系统确认。历史未知路由允许管理员明确承担未回报/迟到领取风险后人工解除升级阻断，而不是声称已证明服务端无未决作业。人工恢复只在本机无领取在途、无持久待提交/回报、无未结束作业或编辑时执行；不重打、不修改服务端结果。保留原异常快照与时间、原因作为独立私有审计，写盘失败不解除阻断；新的领取失败必须重新阻断。

安装结果不确定或健康核验失败时提供单独的人工恢复入口：复用原服务端管理口令验证，不建立新账户体系；页面二次确认且三秒防误触。已知系统安装会话先请求废弃并确认消失，本机实际签名须保持一致、版本须为原版或目标版且对应当前进程；仍在提交/安装时不能强行恢复。保存原事务及人工原因后记为 `manually-resumed`，不记成功或已核验取消；迟到回执不得覆盖人工终态。损坏日志和存储失败不能靠此入口抹除。管理员口令仅在本次操作内存中使用，不落盘或记日志。

人工恢复是用户批准的风险接受，不是自动健康证明。现场应先核对实际作业；系统保留本机已知保护，但不再为历史未知状态引入跨端公共打印契约。该修订替代下文“未知永久无恢复入口”的阶段描述；未完成真机验证前不宣称交付。

AndroidHost 仍是后台打印宿主，不新增业务扫码界面。本轮原生更新页不消费扫码、不改变键盘楔或广播通道；低频维护操作需明确展示当前版本、候选版本、下一动作与失败原因，按钮至少 48dp。安装确认说明应用短暂不可用与数据保留边界，危险动作采用确认倒计时，不能通过安装来绕过未保存编辑。

原有 APK 下载目录只是手工分发草稿。新增 `/api/android-updates` 数据面，与 Windows 分开持久化；打印 API、模板包与作业公共模型保持不变。原生 UI 调用进程内协调器，不在允许任意 CORS 的 `EmbeddedHttpServer` 上新增安装/策略写入端点。已有配置写入、插件安装/卸载、测试打印、作业提交/恢复均须受同一维护门闩约束。

## 发布与信任

服务端管理员口令复用现有升级管理权限判定（高熵 Bearer、TLS 或回环、Origin 核对），只存在内存，不入 URL/日志/localStorage。未配置则禁用管理。发布选择设备 ID，全量须明确确认；每个发布内容、设备范围及确认策略不可变，新增批次另建发布，暂停/恢复仅改可用状态。

发布从草稿复制到独立随机目录，完成真实校验后原子发布，绝不让草稿覆盖影响快照。校验包名必须为 `com.labelframe.androidhost`，读取真实 `versionCode`（含 long 高位）、`versionName`、minSdk、targetSdk、native ABI、debuggable、完整大小、SHA256 及签名证书 SHA256。版本排序只用 versionCode，不用文件名/versionName。正式发布拒绝 debuggable，拒绝拆分 APK 与非宿主产品，拒绝同版本不同内容。

服务端 APK 内容验签必须使用完整 APK 签名验证器；只读 META-INF 证书或 Manifest 不算验签。使用 Android 官方 apksig 与 aapt2 的受限进程适配：固定部署路径、ArgumentList、不经 shell、有界输出/大小/时间；缺工具或信任配置直接不可发布，不回退到文件名。Docker 镜像内置固定摘要工具与正式可信指纹，非容器部署按 DEPLOY 配置；不修改 CI 工作流。部署管理员固定可信发布证书指纹，不能从上传包自动认领信任；客户端还必须与自身已安装签名一致。首版拒绝复杂多签名/轮转而非模糊放行，轮转须另行可信部署。

APK 内增加被签名覆盖的升级协议/服务端兼容范围元数据，校验真实包内容，不接收管理请求自报替代；旧 APK 缺少更新协议元数据只保留手动分发。服务端与客户端分别验证兼容性。客户端固定使用已配置服务端，下载 URL 由发布 ID 构造，不接受任意远端 URL 或重定向到其他源；已签名信任与本机版本检查不依赖服务端自报。

### 服务端校验与存储实现

APK 内 `assets/labelframe-update.json` 固定为 `{ "protocol": 1, "minServerVersion": "1.5.1", "maxServerVersion": "2.0.0" }`；服务端范围为含下限、不含上限。元数据最多 4KiB，ZIP 条目最多 20000、拒绝重复路径，APK 最多 64MiB。版本从编译 Manifest 的 versionCode/versionCodeMajor 组成 long；versionName 仅展示。原生库路径与 aapt2 报告的 ABI 须相符。

校验调用使用固定 `ApkVerifierBridge.java`，由 JDK 17+ 源文件启动器加载部署指定的官方 apksigner.jar 内 `ApkVerifier`。必须完整验证成功、具备 v2 签名、只有一个 signer 且无签名轮转 lineage；证书 DER 的 SHA256 须等于部署预置值。`aapt2 dump badging/xmltree` 提供真实包信息；每次子进程限 30 秒、stdout 1MiB/stderr 64KiB，命令参数不经 shell。工具或指纹缺失时仅发布失败，已有手动分发不受影响。

发布复制到独立 GUID APK 文件，验签成功后以 fsync＋原子替换 JSON 提交发布记录。最多保留 100 个发布批次；同版同摘要可创建不同设备批次，同版不同内容拒绝。全量发布须 `allDevicesConfirmed=true`，只支持 `mode=confirm`。设备状态内存上限 1000 条、带接收时间，重启后重新汇集；它不具有认证效力。候选查询和下载共用设备范围、暂停、签名、版本、SDK、ABI、服务端兼容性判定；客户端提交安装前须再查候选，已提交系统的安装不保证撤销。

## API 草案（兼容新增）

| 端点 | 权限与作用 |
|---|---|
| `GET /api/android-updates` | 管理员；已发布 APK 元数据、设备范围、暂停与策略 |
| `POST /api/android-updates/publish` | 管理员；草稿文件名、设备范围、确认策略；真实校验后快照发布 |
| `PUT /api/android-updates/{id}/pause` | 管理员；只改变暂停状态 |
| `GET /api/android-updates/candidate` | 设备读取；deviceId、currentVersionCode、sdk、ABI、签名指纹筛选；均有长度/数量边界 |
| `GET /api/android-updates/{id}/package` | 下载时复核资格；返回固定快照而非草稿 |
| `POST /api/android-updates/status` | 有界设备自报；版本、事务、阶段、原因；不作为身份认证或发布决策凭据 |
| `GET /api/android-updates/status` | 管理员；同时显示接收时间，陈旧状态明确标注 |

设备自报不是认证；不允许通过报告更改发布、策略或其他设备。暂停在提交安装前最后复核，已经交给系统的安装不能保证撤销，UI 必须说明该边界。

## 后台状态与安装前保护

状态顺序：空闲 → 检查 → 下载 → 已校验 → 等待确认/等待窗口/等待空闲 → 准备 → 已提交安装 → 恢复核验 → 成功；另有不支持、失败、结果未知、需修复。轮询错峰、网络指数退避；一个版本失败安装后不自动循环重装，人工明确重试。中断下载只清理本事务临时文件；缓存最多当前候选与有限诊断，所有 IO 有界。

默认自动下载后由用户确认。安装要求无 dirty/busy、无未结束整批（包括挂起）、无领取在途、无待回报。用户确认不能忽略业务或 dirty。屏幕退出不等于配置保存，失效/未知编辑状态按阻塞处理。

维护门闩必须解决检查与提交竞态：在同一协调机制中停止新路由领取和新本地写操作，已开始整批允许完整结束，结果回报继续；不可仅看某一瞬间当前打印项为空。入门闩前已有领取须完成提交/回报；获取/提交失败且服务端领取结果不确定时不可当空闲。回报映射持久化或在有任何不确定映射时阻断安装，不能重启清空内存后假装无待回报。所有 UI/HTTP/路由/打印测试入口共用门闩；服务重启与插件变更也不能绕过。

## 安装通道与文件安全（必须先验证）

### Android 后台下载与保护层实现

`AndroidUpdateMonitor` 随 `PrintHostService` 后台生命周期启动与排空，不依附 Activity。固定配置服务端（保留反代子路径），禁自动重定向；候选/状态 30 秒、连接 10 秒、单次读取空闲 30 秒、完整下载 5 分钟。缓存最多 `candidate.apk` 与 `candidate.partial` 两个私有文件，每个最多 64MiB；长度、摘要、真实内容校验完成才原子替换候选。检查失败按 30～300 秒加抖动退避，同一发布每服务生命周期最多下载三次；没有安装自动重试器。

Android 侧引入 Google Maven 固定版本 `com.android.tools.build:apksig:8.9.2`（Apache-2.0），Java 小桥完整验证内容、v2、单 signer、无 lineage；.NET 按 JavaSource 生成绑定，不采用反射隐藏 API。PackageManager 只负责读取已验签 APK 的 Manifest，不将其证书读取当作完整验签。签名须匹配本机实际已安装身份，long versionCode 须严格递增；非调试、包名、原生 ABI、minSdk、ZIP 重复路径与签名资产协议分别校验，再与发布快照逐字段对照。客户端还读取原服务端 `/api/server/info` 核对签名资产声明的版本区间。当前受控升级明确要求 Android 9/API28+（签名历史与 long versionCode 平台接口）；较低版本继续既有打印功能，更新检查显示不支持并保留同签名手工升级路径。该实现的设备运行时验签仍需真机证据，构建成功不等于已经验收。

`RouteJournal` 在私有 `files/route-journal.json` 保存原服务端/设备号、领取不确定标记、领取到的完整载荷、本地映射与明确提交失败结果。领取网络请求**之前**先 fsync＋原子提交标记；响应完整落盘后才提交本地队列，提交后才写映射；崩溃在两者之间用原 requestId 幂等重放，不重新打印。终态回报收到成功响应才移除记录，失败与重启继续回报。日志上限 128MiB，损坏、残余临时文件或存储故障 fail closed，不当空日志；有未决状态时禁止把日志关联到新服务端/设备。

未知领取结果（含旧版已配置路由且存在作业库、却没有持久映射的首次迁移）默认阻断安装，不因下一次空领取或服务重启被清除；正常新路由可继续。管理员可通过原生更新页人工接受历史风险：先验证原服务端管理口令，冻结本地写入并核查无已知未结束作业/回报，保存原日志快照和原因后记录 `Acknowledgement`；原 `ClaimUncertain` 历史事实仍保留，只有本次风险的安装阻断被豁免。新领取在请求前撤销豁免，明确成功才恢复历史豁免，失败/重建重新阻断。HTTP 领取响应非法/空值不再过滤丢弃，整次标为不确定。已持久批次回报完才领取新批次，避免无限累计载荷。不据服务端空查询推导安全，不增加领取围栏或自动重打。

`MaintenanceGate` 为进程级写入/编辑 lease 与冻结互斥；HTTP 所有非 GET/OPTIONS、打印发送、路由领取与提交、原生保存/重启和插件变更共用。只读健康与结果回报保持运行。配置/插件子页持有编辑 lease，切后台不释放；回首页按既有行为重新同步配置、丢弃未保存输入后才释放，Activity 销毁释放已消失的编辑会话。因此不仅 dirty，尚处于编辑页的干净表单也保守阻断安装。`MaintenanceSafety` 先冻结再全量检查 Pending/Printing/Suspended（不是最近 N 条、不是当前一张）；已开始的发送 lease 或编辑会话令本次冻结失败，忙态重试不抢占整批。检查异常释放仅本次尚未提交的冻结，恢复中的既有冻结不被另一请求释放。

下载与安装共享 `UpdateOperation` 异步互斥，缓存替换、删除、独立复验、Session 写入与提交不能交叉。安装先获得维护冻结并全量核对作业/路由，复验 APK 后再次查询原服务端候选。应用私有文件写入 PackageInstaller Session 时对实际写入字节重算摘要、长度一致才 fsync；写完后再次查询候选并确认页面仍在前台。准备有五分钟预算，服务代际退出取消准备并排空操作，不能让旧服务在新代启动后提交。暂停只能保证最后资格核对之前被观察到，不能原子撤回已交系统的安装。

### 系统确认、事务与恢复实现

`InstallTransaction` 在私有 files 保存最近事务，限制 256KiB，fsync 临时文件后原子替换。保存原版本、目标版本、签名/包摘要、原配置摘要、服务端与设备号、品牌、外部插件版本/文件树摘要/加载事实。路径异常、损坏、残余临时文件、写入失败均保持冻结；不删除异常文件绕过。`HostApplication` 在 Activity、Service、Receiver 之前恢复冻结。只有健康成功或已证明取消的终态落盘成功才解冻，保存失败不乐观放行。

先持久准备记录，再创建并保存系统 sessionId，提交前先持久 `submitted`。提交抛异常、超五分钟未见目标版本新进程或会话查询为空均不能推定失败已终止。只有尚未提交的准备会话被废弃，或专属系统回执明确失败/取消、系统会话已消失且本机仍是原版本，才能记录取消并解冻。回执走不导出的 Receiver 和显式 mutable PendingIntent，以随机事务 ID 与 sessionId 匹配；迟到待确认回执不能覆盖已有结果。系统成功回执只进入恢复，不直接置成功。

本机信息页内的更新区不消费扫码，不自动丢弃其他编辑页面。页面只有版本状态与一个更新按钮；应用内三秒确认后按需进入系统许可设置，回到前台才继续。`UpdateInteraction` 只衔接当前用户操作，离开页面取消自动衔接；前台准备后系统回执就绪时直接打开安装确认，不再让用户手工打开第三步。后台回执只保存在内存，绝不自行启动 Activity；待确认 Intent 在进程重建丢失时保持结果未知，不伪造确认或自动重装。管理员故障处理入口已按最新用户要求移除，后端恢复逻辑与审计保留而不暴露普通入口。安装请求仅在前台且权限已明确授予时创建；API31+显式要求用户动作，旧系统普通应用走系统默认确认。历史事务终态不能覆盖新下载/失败状态，设备上报与原生 UI 共用投影规则。

已有 `MY_PACKAGE_REPLACED` 接收器拉起服务，恢复线程只在**进程启动时捕获的真实版本**等于目标时检查，避免旧进程读到新版 PackageManager 信息冒充恢复。核对真实安装签名/版本、当前原配置摘要、插件集合/版本/文件字节与加载、原品牌注册存在、本地实际 `/healthz` 响应及原服务端真实注册成功；路由未决仍阻断。无服务端的状态不伪造路由通过。未通过进入 `repair` 并停止自动健康重试，前台可显式重试核验但不重新安装或解冻。未模拟打印证明出纸。监控向原服务端回报事务 ID、阶段与时间接收信息，自报不是认证健康。

管理端下载中心的 Android 页提供独立 `AndroidUpdatePublishing`：APK 草稿选择、去重设备 ID 批次、全量发布显式确认、暂停/恢复以及接收时间与事务标识。发布只传 `mode=confirm`；空范围不等于全量。管理口令仅驻留组件内存，请求禁止重定向，换口令或离页中止在途请求并阻止旧结果回填。相对 API 路径保留部署前缀。设备状态明确为未认证自报，超过五分钟标陈旧，定时更新陈旧提示但不自动轮询；管理员点击读取刷新。正常状态双语，原始诊断原文透传。暂停提示明确无法撤销已提交系统的安装。

阶段边界：安装、原生页面、管理发布页与管理员人工恢复已接线，尚须 Android ART、PackageInstaller 回执、设备新进程和中英文真实界面验收。人工恢复不等于自动核验未知路由安全，不提供清日志入口，不将构建或单测当真机实升。

DT50 当前已验证固件为 Android 11/API30、DT50S、RKQ1.210728.002 release-keys；厂商 `android.device.DeviceManager.installApplication(String)` 仅视为请求提交。类存在不足以判定机型支持，支持配置须限制到实际验证的机型/系统范围，其余明确系统确认安装回退。

**尚未证明安全的环节**：预研 `/data/local/tmp` 不可读，公共 Download 可读，但随机文件名、只读 chmod、安装前再次 SHA256 都不能单独消除共享存储路径替换竞态。实现前优先实测应用专属外部目录在本固件下的厂商可读性与其他普通 UID 不可写性（包括旧 target 与有存储权限应用）；或采用厂商支持的只读描述符/受限 ContentProvider。不得扩大私有数据目录权限、启用 Root/全盘管理或为安装放宽所有文件权限。

只有能证明不可由其他普通应用替换的交接对象，才允许走厂商静默安装；校验/原子落位/交接期间保持对象身份与权限，安装完清理精确事务路径。若固件只有共享路径接口且无法满足该条件，不能宣称静默交付，记录 AC-07 阻断并转系统 PackageInstaller 确认路径；该裁剪影响核心交付，须向用户解释并请求决策，不私自以不安全共享文件上线。

标准回退通过 PackageInstaller Session 从私有文件写入并 fsync，使用系统确认结果；普通应用权限不能承诺静默。请求用户动作在前台展示，后台只显示待确认，不强拉系统界面。原应用签名不同拒绝更新，不卸载、不清数据、不伪造降级恢复。

### DT50 安全交接阻断实测（2026-10-27）

仅在授权设备 `01792423013057` 上用两个独立非调试包验证，未覆盖或启动原宿主。安装方普通 UID 10209、targetSdk 36、无权限；对抗方 UID 10210、targetSdk 28，READ/WRITE_EXTERNAL_STORAGE 已授予，运行时确认 `legacy=true`、写权限检查为 0。安装方自行从签名包内资源复制候选到 `getExternalFilesDir(null)/handoff/candidate.apk`，未由 ADB 向该目录投放 APK。候选真实 versionCode 12，基线 11；这是文件交接测试，不是正式宿主后台下载验收。

|---|---|

## 持久事务与真实健康

提交安装前原子记录事务 ID、候选真实版本/摘要、原版本/签名、原配置摘要、插件集合与版本/加载状态、服务端地址与设备号、阶段/时间/失败计数。写入失败不安装；提交前重查发布资格、包完整性、真实签名与系统/ABI。厂商 true 不置成功，false/异常也保留清晰阶段与证据。

MY_PACKAGE_REPLACED 或下次冷启动首先恢复事务并保持门闩，再启动本地 API/插件/注册健康通道（业务领取仍冻结）。必须实际版本等于目标、签名一致、API 就绪、原配置与插件无丢失/加载错误、原品牌未回退、原服务端注册成功；没有配置服务端不得伪造路由通过。这里检查真实服务恢复，不发送模拟打印来证明物理输出成功。健康成功原子持久化后解除门闩并回报。原版未变明确安装失败，版本异常/健康异常进入需修复，不无限重启或自动降级；厂商安装超时结果未知时不能释放门闩允许打印后再被迟到安装打断。

旧版需一次同签名基线部署获得新能力，不能把 ADB 首次安装计作自动更新；后续高版本必须走产品下载/校验/安装链。DT50 原数据、配置和 APK 先备份，先核查签名与安全恢复条件；非调试可使用同一测试签名的 Release 构建验证 runtime 行为，但不能冒称正式发布私钥验证，签名来源与证据必须明确。
