# LabelFrame 需求文档

## 1. 愿景

**方便仓库完成标签打印，提高办公效率。**

- 方便 = 少步骤、就近打印、零学习成本、少故障、少求人。
- 效率 = 打印快、能批量、不重复劳动、不出错、融进业务动作。

## 2. 角色

| 角色 | 关注点 |
|---|---|
| 操作工 / 仓管员（PDA） | 就近、快、单手可操作、零学习、失败要明确 |
| 文员（PC） | 批量、补打、不用管打印机 |
| 管理员 / IT | 一次配置、多设备可复制、故障可解释 |
| 业务系统（WMS 等） | 接入简单、有结果回执、不依赖打印机细节 |

## 3. 场景

### 3.1 物料码（最高频）

- 收货：打新码；PDA 单打为主，PC 批量辅助，PDA 偶尔也批量。
- 出库拆分：一次请求打 1~2 张（内容可不同，视旧码是否作废）。
- 补打：1 张；多为旧码破损；偶尔扫旧标签原样补打。

### 3.2 库位码

- PC 批量为主，低频，一次打很多，需按顺序出纸（边打边贴）。

### 3.3 容器码

- 低频，多数项目不管控；架构留位，不投入。

### 3.4 备料标签（扩展场景）

- 贴在托盘上，标记已备物料集合；按新增模板扩展，不需要新能力。

## 4. 打印模式

- **就近直连**：PDA 网页 → 本机宿主 → 本地打印机。
- **服务器定向投递**：业务系统 → Server → 发起设备宿主 → 打印机；多人 / 多设备并发互不干扰。
- **Linux 测试客户端**：Server → Linux 无头宿主 → Log 模拟输出；提供版本化容器镜像，用于容器化测试发布候选与已发布稳定组合，不连接物理打印机。
- **一次请求 = 多张**（labels[]），批量异步，提交即返回 jobId。
- **PDA 单张同步快捷路径**：本地往返快，可等结果。
- 模板由 Server 集中管理（CRUD + 模板包导入导出），领取作业时把模板与图片资源一并投递给目标宿主。

## 5. 底线（不可妥协）

1. 条码必须可扫：统一按打印机 DPI 渲染整版 1bpp 位图并以品牌图片指令发送（默认 ZPL `^GF`，插件分派如 TSPL `BITMAP`），禁止低分辨率缩放。
2. 不重打、不漏打：幂等 + 持久化 + 断点续打。
3. 结果必须回执：jobId + 状态 + 失败原因。
4. 缺数据不打半张：契约校验，必填缺失拒绝打印。
5. 中文必须能打：整版位图渲染中文字体（内嵌优先、回退系统字体），不依赖打印机固件。
6. 故障可解释：错误码 + 人话消息 + 日志。
7. 并发不串标：设备定向 + 每台打印机串行。

补充语义：
- 批量打印中途缺纸 / 离线 → 作业挂起，恢复后续打；单张 → 直接失败可重试。
- 不承诺「断网可用」（PDA 网页断网时通常连业务数据都拿不到）；靠队列与幂等保证网络抖动下不丢作业、不重复打印。

## 6. 能力分层

### P0（第一版）

- 契约 / 版式模型；数据校验；ZPL 编码器；中文渲染。
- 作业队列（持久化 / 幂等 / 挂起恢复取消 / 批内顺序）；提交与进度 API。
- 设备注册与定向投递；Server 测试入口。
- Client Host：Windows 客户端支持本地 HTTP、TCP 9100、Windows 驱动、Zebra SDK 与日志模拟；Linux 无头客户端首版仅支持 Log 模拟。
- 错误码 + 本地日志。

### P1（第二版）

- 预览渲染（设计期）。
- 单机模板管理：CRUD + 模板包导入导出。
- 模板按项目 / 客户分组。
- 失败项单独重打。
- 打印机测试页 / 在线状态。

### P2（待需求）

- 其他打印机指令集（CPCL 等；TSPL 已交付 Windows 端——官方插件随客户端安装包附带；PDA 侧按真实需求另行评估）。
- PDA 蓝牙传输（自 P1 降级：PDA 宿主本身走 IP 打印、不依赖蓝牙，出现真实蓝牙打印机需求时按传输插件接入，见 ROADMAP「待需求」）。
- 打印历史统计。
- 多打印机并行。
- WMS 模板下发（复用模板包格式）。

### 兼容性

- .NET 10；Windows 客户端要求 Win10+（Zebra SDK）；Win7 / Win8 的 net48 版宿主有真实需求再做。

## 7. 边界（不做）

- 报表 / 单据打印（其他项目的领域）。
- 业务数据管理：编号规则、条码内容生成、物料 / 库位数据。
- 打印计数、库存联动（如需，只提供事件接口）。
- 业务系统页面本身（我们提供打印服务，不做业务 UI）。
- 云打印 / 跨地域集群。
- 多语言（仅 Web UI / API 错误消息 / PDA 宿主三端支持 zh-CN + en；打印内容 / 模板、安装链、日志、RTL 语言仍不做）。

## 8. 成功衡量

| 类别 | 指标 | 目标 |
|---|---|---|
| 底线验收 | 条码一次扫码通过率 | 100%（真实扫码枪逐张扫） |
| 底线验收 | 重复打印 / 漏打次数 | 0 |
| 效率 | 提交到出纸的系统耗时（不含打印机物理速度） | 本地 < 1 秒 |
| 效率 | 批量 50 张连续打印成功率 | 100%（排除缺纸 / 卡纸） |
| 体验 | 终端操作步骤 | 1 次动作 |
| 体验 | 管理员配置一台新设备 | 一次性 ≤ 5 分钟 |
| 业务 | 试点前后打标签耗时对比 | 下降 ≥ 30% |

试点方法：
1. 先测基线：现有方式打 50 张物料码，记录耗时、失败率、补打次数、IT 求助次数。
2. 接入 LabelFrame 后同指标复测。
3. 真实扫码枪随机抽 50 张逐张扫。
4. 连续 100 张压力验证（含重启 / 断网场景）。

试点先盯 4 个关键项：扫码通过率、重打 / 漏打率、批量成功率、耗时对比。
