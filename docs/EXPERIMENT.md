## 已授权的产品方向

浏览器只有匿名公开区与 admin：匿名只看公开下载、静态帮助、登录入口及必要对外连接地址；模板、设计、数据打印、设备、历史、插件、日志和下载管理均需 admin。导航、路由、后端一起保护；退出清敏感状态、取消请求并停止轮询。

机器接入认证与页面登录分离。可选客户端验证：关闭为信任局域网，开启后一次配对得到每设备独立长期凭据；设备 ID/IP 不是凭证。正常重启、断网和升级不重配。关闭保留凭据，再开启继续有效；启用前展示受影响设备与集成并确认。业务系统独立接入密钥。短时六位单台码与约 30 分钟批量码只是待设计候选。

所有管理写操作始终认证，不能留下匿名等价入口。信任模式仍允许匿名运行接口，业务数据并未完整保护，必须明确残余风险。远程登录、配对和长期凭据要求可信 HTTPS，本机回环可例外；可信内网 HTTP 便利模式若保留必须明示风险。不得忽略证书验证或自创加密协议，不强迫逐台装证书。重大证书部署取舍须用户决定。

保留已有升级签名、快照与传输约束；不扩大 TCP9100/TSPL/Zebra 打印机链路范围。回调目标绑定可评估，不一刀切禁止合法内网。不是无限扩张的安全平台，不对真实环境实施攻击或安装。

## 治理审计（2026-10-29）

最新基线纠偏：1.6.0 的 `docs/design/update-publishing.md` 已替代旧升级管理口令要求，当前发布管理允许可信内网同源 HTTP；跨源拒绝不是身份认证。安全实验须重新建立统一 admin 授权，不能假定旧 Bearer/TLS 限制仍在；包签名、版本/兼容检查与不可变快照保留。传输限制是本实验目标，不是来源现状声明。

治理 Issue：[实验 #1](https://github.com/CSJ608/LabelFrame-security-experiment/issues/1)。

## 分阶段计划与验收

1. 治理与隔离：本 Issue/PR 验证 Fork 来源、remote、禁发状态、规则覆盖；仅文档/流程，不声称已完成安全功能。
2. 安全设计：独立 Issue，枚举实际端点和共享宿主兼容；制定公开/admin/设备/集成能力矩阵、会话/CSRF/限流、引导与恢复、配对与持久化、HTTPS/代理边界、开关影响预检及回退。先更新 DESIGN 再写实现。
3. 最小原型：先 Server 管理认证和公开边界，增加负向测试与前端登录/路由/退出；然后在已定契约内逐步做机器凭据。每块独立验收，未接通的 UI 或客户端不得声称已保护。
4. 隔离验证：模拟设备与业务调用、纯测试数据、临时 DB、回环端口；验证匿名拒绝、越权拒绝、CSRF、HTTPS/代理伪造、重启/凭据保存与开关语义。保留旧 WinHost 兼容测试，不跑真实打印或安装。

基础检查：`git diff --check`、定向 dotnet 测试；有功能改动执行适当 build/test（排除 Perf/Soak）；前端改动使用版本匹配工具链 lint/test/双模式 build。未执行、失败和环境局限逐项记录，不借用上游绿灯。
