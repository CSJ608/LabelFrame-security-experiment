# 插件卸载与重启保护修复验收

日期：2026-10-24。关联任务：[#451](https://github.com/marci-labs/LabelFrame/issues/451)、[#452](https://github.com/marci-labs/LabelFrame/issues/452)。用户确认其他试用项没有问题，本次只处理卸载后被重新安装、无编辑误报未保存两个缺陷；真实打印机与额外正式签名包按用户决定免验，不冒充已执行。

## 修复前后

- TSPL/Zebra 回归在旧实现均复现：卸载后启动迁移再次创建插件目录。修复后持久化卸载意图，连续启动及更高附带版本均不补装；主动安装成功才清除。标记写入失败保留原包，目录删除失败保留意图，同版本主动重装可修复残缺包。
- 旧 Settings 在机器地址异步到达后将无编辑视为 dirty；地址保存规范化后也可能继续 dirty。现在未编辑字段跟随配置，真实草稿仍保留并受保护，可定位、保存或放弃。
- 旧活动上报在前一请求未结束时跳过重启前的最终状态。回归复现后改为等待并发送最新状态；页面关闭的 keepalive 仍立即发送。

## 真实浏览器

复现脚本：`web/scripts/verify-plugin-restart.mjs`，系统 Edge 加载实际构建产物；API 为隔离夹具，服务器离线，不连接用户安装实例。

1. 插件深链启动，延迟加载不同机器地址；卸载后立即重启成功，dirty=false。
2. 真正编辑地址后回插件页，重启被阻止，dirty=true；页面提示具体编辑位置。
3. 放弃地址草稿后重启成功。
4. 保存带空白与尾斜杠地址，规范化后重启成功。

结果：[browser.json](browser.json)，页面异常为零。截图：[卸载后重启](offline-uninstall-restart.png)、[真实编辑阻止](edited-address-blocked.png)。

## 隔离 Windows 完整进程

按 clean-win-vm 技能在执行前后还原 baseline-clean-winrm。使用修复后发布的真实 WinHost（源码产品版本仍为 1.4.0），启动 WebView2/托盘，通过真实本机 API 驱动卸载与重启；本次没有安装候选 MSI，也没有模拟点击托盘。详见 [vm-result.json](vm-result.json)。

- 旧连接首次启动自动安装附带 TSPL 1.4.4。
- 实际卸载、实际重启后插件缺失；换入更高附带 1.4.5 再次重启仍缺失，标记存在。
- 主动 API 安装 1.4.4，实际重启后自动升级到附带 1.4.5，loaded=true、loadError=null，标记清除。
- 各次连接配置 SHA256 不变，新实例标识均变化，最终仅一个打印客户端，原用户会话保持。
- 测试会话报告 dirty=true 时实际重启返回 409；关闭该会话后可重启。这里的编辑输入为协议测试，实际页面编辑由上一节覆盖。
- 导出证据后已还原基线，核验测试目录、计划任务、测试客户端均不存在。用户本机安装、配置和进程未被修改。

## 交付边界

用户更新候选后仍需复测这两个修复，Issue 保持待验收；其他用户已接受的项目不重新扩展验收。旧版本没有记录的卸载意图无法事后推断：需要在修复版执行一次卸载再测试重启。无发版 tag；本地更高版本安装包仅供手动复测，不作为自动升级验签测试。
