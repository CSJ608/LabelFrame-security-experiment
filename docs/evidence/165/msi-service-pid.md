# 普通权限安装误选服务修复

2026-10-24，#452 用户反馈本地候选 1.4.5 无法安装。Windows Installer 11:53 的事件 11722 指向 `ShutdownWinHost`，最终 1603。用户原客户端继续运行，未发生新版本启动。

## 原因与复现

非提升权限下，更新服务 PID 11648 的 Win32_Process.CommandLine 为 null；旧筛选把 null 视为“不含 --update-service”，选中该服务并要求它提供打印 API。Win32_Service 仍可读取 LabelFrameClientUpdater 的 PID。

从实际 MSI 提取选择部分，只读执行（不运行 shutdown）得到：

| 包 | 选择结果 | 服务 PID |
|---|---|---|
| 1.4.5 原包 | 11648，SessionId=0，CommandLine=null | 未查询 |
| 1.4.6 修复包 | 2972，SessionId=2，--restart-plugins | 11648，已排除 |

修复先从 Windows 服务记录排除更新服务 PID，再做原命令行角色筛选；无权限读取命令行的非服务进程仍保留并接受安全预检，查询服务失败仍阻断安装。

## 验证

- `verify-msi-ui.ps1` 从实际 MSI 经过引擎 Formatted 转换后的命令执行回归，新增 null/空服务命令行、仅服务、未知非服务命令行；旧包明确失败，新包全部通过。原打印客户端、等待器、仅服务与等待器回归继续通过。
- Release build：0 警告0错误；完整 .NET 测试排除 Perf/Soak，串行 1,285 项通过。前端无变更，本轮不以历史测试冒充重跑；CI 仍执行完整前端门禁。
- 新包 MSI 结构、角色选择、依赖基线断言通过。追加的本机 x86 PowerShell `.ps1` 只读检查被该进程默认执行策略阻止，未计通过、未修改系统执行策略；实际 MSI 安装验证见下。
- 按 clean-win-vm 在测试前还原 baseline-clean-winrm。真实安装 1.4.4（退出码0）并启动交互会话客户端，后台更新服务运行；实际升级新包1.4.6（退出码0），旧客户端成功退出，服务由 MSI 重建并 Running。手工触发测试计划任务再打开客户端，本机 API 就绪且实例变化；此步骤不作为安装完成自动打开的证据。
- VM 实例由 `ed0de206559947f2a94acce4b07e246f` 变为 `0b03ee1b7dac4029b2c42ae5183e3e96`；服务 PID 1980→3284；注册表实际安装版本1.4.6。VM 的 MSI 从管理员远程会话执行，普通权限不可见命令行场景由本机只读复现与实际 MSI 回归覆盖，不冒充普通权限向导点击。
- 原始 VM 结果与 verbose 安装日志已导出本地 artifacts；测试后还原基线，不留测试目录、计划任务或更新服务。

## 候选与边界

手动候选 `LabelFrame-Client-1.4.6.msi`，SHA256 `1EAF4A69FDC877B7AFF78F102E0365ABDC79AD2A94DED2AA712634FD930FED86`。包含 #456 插件卸载/重启修复；官方附带包仍为1.4.5，不因安装器修复重复升级插件。候选版本临时用于构建，源码产品版本已恢复1.4.0，无发版tag、无签名信任变更。用户本机进程、服务及配置未改动。

用户应改用1.4.6手动安装并复测卸载后重启。原1.4.5候选不再推荐使用；Issue 保留待验收。
