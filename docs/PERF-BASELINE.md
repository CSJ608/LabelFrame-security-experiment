# 性能基线（v2 · 2026-09-07 · 开发机 i5-12500H / .NET 10.0.11）

> 测试方法与运行方式见 `scripts/run-perf.ps1`；CI 每周夜间跑（`.github/workflows/nightly-perf.yml`）。
> 本文档记录当轮数据与通过标准，供后续改动对照。
> v2 = 迭代 39 性能优化批次（Worker 信号量唤醒 / SQLite 领取写合批 / SKBitmap 池，决策 #92）后的基线；v1 数据以「旧」标注保留对照。

## 一、微基准（BenchmarkDotNet · ShortRun）

打印热路径 = Skia 整版渲染 → 1bpp 位图 → ^GF 编码（文本+条码+二维码三元素标签）。

| 规格 | 整链路单张（v2） | 分配（v2） | 整链路单张（v1 旧） | 分配（v1 旧） |
|---|---|---|---|---|
| 60×40mm @203dpi | ~0.9 ms | **390 KB** | ~0.72 ms | ~990 KB |
| 100×60mm @203dpi | ~1.5 ms | **756 KB** | ~1.7 ms | ~2.2 MB |
| 60×40mm @300dpi | ~1.3 ms | **811 KB** | ~2.0 ms | ~2.1 MB |
| 100×60mm @300dpi | ~2.7 ms | **1.61 MB** | ~3.4 ms | ~4.9 MB |

**结论**：SKBitmap 池化（决策 #92③）后**每张托管分配降 61%–67%**——被池化的整版像素暂存（Bgra8888，60×40@203 为 600KB、100×60@300 为 3.2MB）不再每张新建，剩余分配为 1bpp LabelBitmap + ^GF ZPL 文本 + ZXing 中间态（输出物本身，不可池化）；SKBitmap 原生像素内存同步复用。渲染步 Gen0/Gen2 收集频率大幅下降，50 张以上连打的 GC 压力已从「可感知」降为轻微。耗时数据本轮在本机 ~39% CPU 负载下采集（StdDev 偏大），与 v1 差异在噪声范围内——权威耗时以 nightly 隔离环境为准。

### 批量规模伸缩（BatchScalingBenchmarks · 203dpi · 100×60mm · ShortRun）

一次作业 N 张：渲染+编码全部 N 张 → SQLite 入队（含临时库初始化）总耗时 / 总分配。

| 张数 | 简版（单条码） | 密版（文+码+QR+线） | 分配（v2） | 每张均摊（v2 / v1 旧） |
|---|---|---|---|---|
| 1 | ~7.2ms | ~8.1ms | ~0.9MB | — |
| 2 | ~10.1ms | ~10.5ms | ~1.7MB | ~0.85MB / ~2.3MB |
| 50 | ~130ms | ~145ms | ~42MB | ~0.84MB / ~2.3MB |
| 200 | ~482ms | ~595ms | ~165MB | ~0.84MB / ~2.3MB |

**结论**：
- **线性伸缩保持**（无超线性退化）：50→200 张每张均摊稳定 ~0.84ms 耗时 / **~844KB 分配**（v1 为 ~3ms / ~2.3MB）；
- **分配量降 63%**：200 张批量 458MB → **165MB**——Gen0/1/2 高频回收显著缓解（Gen2 每千次操作 5000→本轮 10000 次 / 每 200 张批计 10 次，单次 μs 级）；
- 密版 vs 简版成本差 <15%（元素复杂度不是主要因子，面积和 DPI 才是）。

**关于打印模式**（v2 基线时点口径）：当时仅一种打印路径——整版位图 ^GF（迭代 15 决策 #50 已删除矢量 ZPL），基准覆盖的就是该路径的完整系统侧成本；传输层差异（TCP 9100 ~20KB/张 vs Zebra SDK vs winspool）由各传输插件承担，系统侧链路相同。此后 Zebra 原生指令编译（迭代 78-80）与 TSPL 插件（迭代 143，决策 #195——原生编译 / `BITMAP` 二进制 / 图片编码器分派）引入了非 ^GF 编码路径，**尚未纳入基准**——需要时在 Benchmarks 项目新增对应基准即可。

## 二、端到端延迟

### WinHost 单张全链路（提交 → 渲染 → 编码 → 入队 → Worker 发送 → 终态）

30 张逐张（60×40mm @203dpi，零耗时传输）：**p50 ≈ 9ms / p99 ≈ 79ms**（通过标准 **p50 < 20ms** + p99 < 500ms；v1 为 p50 ≈ 205ms / p99 ≈ 240ms，仅 p99 < 500ms；CI 分档口径见环境说明——迭代 99 / 决策 #155）。

**迭代 39 变化（决策 #92①）**：`JobPrintWorker` 空转等待改为入队信号即时唤醒（原 200ms 轮询周期），延迟主体收敛为渲染+编码 ~1ms 与入队 / 领取开销；p99 为首张 JIT / 字体加载预热。信号在存储写入提交后发出（提交 / 恢复 / 失败项重打 / 启动恢复中断四条路径），5s 超时兜底防信号遗漏（正常路径不触发）；「探测有 Pending 但领取落空」（挂起作业等）保留 200ms 周期。

### Server 路由全链路（提交 → 领取 → 回报，TestServer 进程内）

并发 1 / 5 / 20 虚拟设备 × 每设备 20 作业（TestServer 进程内），全部 0 错误：

| 并发设备 | p50 | p95 | 判定 |
|---|---|---|---|
| ≤ 5（典型规模） | ~4ms | < 2s | 通过 |
| 20（压力位） | 本机负载下超阈（见下） | 本机 A/B 2954–3422ms（旧 3741ms） | 阈值由 nightly 隔离把关 |

**发现（SQLite 单写者特征，迭代 39 复核）**：20 设备并发时写事务竞争单写锁、busy_timeout 排队放大尾部——**主体延迟不受影响（1/5 设备 p50 恒 4ms），无错误无丢失**。迭代 39 实施领取路径「Touch + Claim」合并为单写事务（决策 #92②），每轮领取少一次锁排队：本机 ~39% CPU 负载 A/B 实测无合批 p95 3741ms vs 合批 2954–3422ms（约 -10~-20%）。**架构级合批（写队列串行化 / 提交缓冲 / 换存储）明确不做**：当前局域网规模 p50 不受影响、无错误无丢失，量化依据见 DESIGN 决策 #92。
本轮本机（~39% CPU 负载）20 设备两臂 p50 均超 50ms 阈值，属 DESIGN §7 既有记录的环境敏感特征（CPU 40%+ 超阈、0 错误），非回归；隔离环境数据以 nightly 为准。

**CI（nightly 共享宿主）分档口径（迭代 99 / 决策 #155，2026-09-22）**：GitHub windows-latest 为共享多租户宿主——4 轮实测（8-31 / 9-7 / 9-14 / 9-21）Routing p50 轮间抖动 10-300 倍（device-5：60ms→过→51ms；device-20：344→401→1169ms），而同代码本机复跑全达标（device-1/5/20 p50 = 9/7/6ms）——CI p50 无回归判别力，判定口径改为「无错误 + p95 分层」（≤5 设备 < 5s、20 设备 < 10s；按实测极值 959ms / 3061ms 留 ≥3 倍余量），p50 仅观测输出；WinHost 单张放宽 p50 < 100ms / p99 < 1s（镜像 `win25-vs2026/20260907` 起实测 p50=31ms / p99 181-210ms）。**掩盖事故记录**：迭代 99 前 Perf 两条 `dotnet test` 合写一个 pwsh 步骤、步骤退出码只取末条命令——8-31、9-7 两轮 Server 断言失败被吞为「成功」（日志实有 FAIL），9-14 起 WinHost 亦超阈才首次显红；已拆独立步骤修复（#198）。

## 环境说明

- 数据采自开发机（i5-12500H，单机 TestServer 进程内），CI 夜间数据以 Actions 日志为准；
- **v2 耗时数据在本机 ~39% CPU 负载下采集**（BenchmarkDotNet StdDev 偏大、分布多峰），耗时结论以分配数据与 nightly 隔离环境为准——分配字节数不受负载影响，可直接对照；
- Perf/Soak 测试打 `Trait` 标签，日常 `dotnet test` 与 ci.yml **不执行**（避免时长与阈值抖动），显式过滤运行；
- **判定口径分环境（迭代 99 / 决策 #155）**：本地（开发机）严格口径——Routing p50 < 50ms + p95 分层（≤5 设备 < 2s、20 设备 < 5s）、WinHost 单张 p50 < 20ms / p99 < 500ms；GitHub 共享宿主（`GITHUB_ACTIONS=true`）——Routing 判「无错误 + p95 分层」（≤5 设备 < 5s、20 设备 < 10s）、p50 转观测，WinHost 单张 p50 < 100ms / p99 < 1s。恢复 CI 硬 p50 阈值的触发条件：换自托管 / 独占宿主 runner，或 CI p50 分布连续 4 轮稳定（变异 < 2 倍）。
